# SmartChart v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the journey prototype the SmartChart app at `/`: strict TypeScript engine, React shell, legacy app removed, one approved gallery (`starters.json`), and an empty state that shows what SmartChart makes.

**Architecture:** The engine (`docs/design/proposals/{v5,journey}`) moves to `src/engine/` and is ported file by file to strict TS with no behaviour change; the existing unit tests (moved to vitest) prove each step. A React + Tailwind shell in `src/app/` replaces `journey/app.js`, mounting slides through refs with the engine's `mountSlide`. The v5 examples become `starters.json` (the only example set), are rewritten from FinBridge to Acme under structure, fit and count locks, and feed the landing gallery and the Add slide view.

**Tech Stack:** React 18, TypeScript ~5.6 (strict), Vite 6, Tailwind 3 + shadcn/ui, lucide (npm), vitest, @playwright/test, Vercel functions (`api/`).

**Spec:** `docs/superpowers/specs/2026-09-27-v1-app-design.md` (read it first; section numbers below refer to it). Background: `docs/superpowers/specs/2026-09-26-slide-system-architecture-design.md`, `docs/superpowers/specs/2026-09-27-colour-allocator-design.md`.

## Global Constraints

- Branch `v1/journey-app`. Baseline commit for every "as at" comparison: `788f4d7`.
- TypeScript `strict: true`; no `any` (use `unknown` and narrow); no inline styles in React components (`style={...}` forbidden). CSS custom properties set on slide DOM by the engine (`el.style.setProperty`) are allowed, since that is engine code, not a component.
- Components over ~300 lines are split.
- Engine port is mechanical: same function names, same arguments, same behaviour. A behaviour change needs its own commit with its own reason.
- `slides.css` is imported unchanged. Slides are the calibrated v4/v5 look.
- Deck storage key stays `smartchart.journey.decks.v1` and the stored shape stays compatible (spec 2).
- API: only `glm-5.3-flash` and `glm-5.3` reach GLM; only `~typesafe/jev-latest` reaches OpenRouter. Keys never reach the browser.
- The starters: exactly 17, in the order of `v5/examples.js` at `788f4d7`; FinBridge → Acme; no real brands; structure, fit and count locks (spec 4.1). Colour problems are fixed in the colour allocator, never in starter content.
- Landing gallery thumbnails: 2–3 per row, never under 420px wide. (The Add slide filmstrip previews at 180px; its featured slide is the full-size view.)
- **CLAUDE.md stays current and concise** (about 30 lines: product line, stack, commands, structure, rules, pointers). Any task that changes structure, commands, rules or the gallery updates CLAUDE.md in the same commit. Tasks 1, 7, 11, 12 and 15 have explicit steps for it; Task 19 re-reads it against the code.
- **`docs/product/PRODUCT_INPUT.md` is the guiding philosophy** (spec 5.0), especially for the landing: slides are the hero, restrained chrome, the gallery is the closed menu, Consulting/Pitch is a first-class choice, and copy is answer-first and concise. Do not edit its philosophy; only fix stale file pointers (Task 12).
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A deck saved by the prototype** (with `thread` as an HTML string, `working` as an array, `items[].checks`) must open in v1 with its slides, style, palette, accent and chat visible. Test in Task 8.
2. **Storage blocked or full** (private window, quota): the app still works; one warning in the chat; nothing throws. Test in Task 8.
3. **Double-clicking a gallery tile, or clicking one while the page is busy,** must create exactly one deck with one slide. Test in Task 17.
4. **Add slide inside a pitch deck with a custom accent** must show every starter in the deck's own style, palette and accent, and insert after the *current* slide (not at the end); section numbering must follow. Test in Task 18.
5. **Opening the app with the model API down** (`/api/health` fails or reports not live) must still show the landing gallery; picking a slide still works; sending a prompt shows a clear error in the chat instead of hanging. Test in Task 17.

```ts
import type { Plugin } from 'vite'
import { loadEnv } from 'vite'
import type { IncomingMessage, ServerResponse } from 'node:http'

type Handler = (r: Request) => Promise<Response> | Response
const ROUTES: Record<string, { method: 'GET' | 'POST'; load: () => Promise<Handler> }> = {
  '/api/glm': { method: 'POST', load: async () => (await import('../api/glm')).POST },
  '/api/jev': { method: 'POST', load: async () => (await import('../api/jev')).POST },
  '/api/health': { method: 'GET', load: async () => (await import('../api/health')).GET },
}

export function toWebRequest(req: IncomingMessage, body: Buffer): Request {
  const headers = new Headers()
  for (const [k, v] of Object.entries(req.headers)) if (typeof v === 'string') headers.set(k, v)
  const url = `http://${req.headers.host ?? 'localhost'}${req.url ?? '/'}`
  return new Request(url, { method: req.method, headers, body: req.method === 'GET' ? undefined : body })
}

const readBody = (req: IncomingMessage) => new Promise<Buffer>((ok, fail) => {
  const parts: Buffer[] = []
  req.on('data', (c: Buffer) => parts.push(c)).on('end', () => ok(Buffer.concat(parts))).on('error', fail)
})

async function send(res: ServerResponse, r: Response) {
  res.statusCode = r.status
  r.headers.forEach((v, k) => res.setHeader(k, v))
  res.end(Buffer.from(await r.arrayBuffer()))
}

/** Dev only: serves api/*.ts like Vercel does, with the local spend guard the old server.mjs had. */
export function apiDev(opts: { cap?: number } = {}): Plugin {
  let calls = 0
  return {
    name: 'api-dev',
    apply: 'serve',
    configureServer(server) {
      Object.assign(process.env, loadEnv(server.config.mode, process.cwd(), ''))
      const cap = opts.cap ?? (Number(process.env.CALL_CAP) || 2000)
      server.middlewares.use(async (req, res, next) => {
        const path = (req.url ?? '').split('?')[0]
        const route = ROUTES[path]
        if (!route) return next()
        if (req.method !== route.method) return send(res, Response.json({ error: 'method not allowed' }, { status: 405 }))
        if (route.method === 'POST' && ++calls > cap) return send(res, Response.json({ error: `call cap of ${cap} reached; restart the dev server` }, { status: 429 }))
        const handler = await route.load()
        await send(res, await handler(toWebRequest(req, await readBody(req))))
      })
    },
  }
}
```
