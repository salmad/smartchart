## What confused the agent, by where to fix it

### tool result

- **a02#1** R11 kept failing even when the slide already said '18 months'. It only cleared once '18mo' was put into a step's `when` label. That pushed the agent to state a made-up fact: Q4 equals month 18.. “R11: Headline figure 18 is not on the slide”: The first slide's subtitle was '£2m buys 18 months to £1m ARR.' and R11 still failed. It also failed on the titles '18 mo' and '18 months'. The check seems to accept '18' only in the body, or only when glued to a unit. So the agent tried variants until one passed, and ended with 'Q4, 18mo', which misstates the timeline. Fix: Make R11 match the number in the title, subtitle or body, with or without a unit ('18 months', '18 mo', '18-month'). Also make R11 advisory when the figure is a time horizon and not a data value.
- **a02#1** R4 required the focus to be highlighted in the title. That clashes with the pitch rule that the title is a 1–3 word topic and the claim goes in the subtitle. The agent swapped 'What £2m buys' for '[[£1m ARR]]' and lost the link to the raise.. “R4: Focus element is not highlighted in the title with [[…]]”: The template's own example highlights in the subtitle (title 'The plan', subtitle '[[£5m]] to a funded book.'). But R4 told the agent to put the highlight in the title, so the agent turned the topic title into a single milestone. Fix: For pitch topic titles, let R4 pass when the focus is highlighted with [[…]] in the subtitle. Reword it as: 'Focus element is not highlighted with [[…]] in the title or subtitle.'
- **f02#1** FY25 is not the highlighted column. The 'auto' focus resolved to the EBITDA row, which also turns FY24's (0.6) gold.. “"resolved":{"focus":"item8"}”: The agent passed focus 'auto', and SmartChart picked the EBITDA row even though the title highlights [[FY25]], which names a column. The agent accepted that choice without checking it against its own title. Fix: When the title's [[…]] text matches a column label, resolve 'auto' focus to that column (columns[i].focus), not to a row. Otherwise, add a warning: 'Title highlights FY25 but focus is a row; set columns[2].focus'.
- **f02#1** check_slide confirmed the mismatched highlight as correct, so the agent saw no reason to change it.. “{"id":"R4","ok":true,"msg":"One focus element, highlighted in the title"}”: R4 and J4 ('Highlight matches the claim') passed even though the [[FY25]] in the title and the highlighted EBITDA row point at different things. Both checks told the agent the highlight was right. Fix: Make R4 check that the title's [[focus]] text matches the label of the focused element (the column header or the row label), and fail when it doesn't.
- **f02#1** R8 was left failing (no source or footnote).. “R8: Figures with no source or footnote: say where they come from”: The agent was right not to invent a source; the guide says 'Never write a source the user did not give.' But R8's wording pushes toward inventing one. The agent also told the user the figures are 'internal management figures', which the user never said. Fix: Reword R8: 'No source given. Ask the user for one; never write one they did not give.'
- **n01#1** The title credits the whole doubling to June's Xero launch, but the data shows June added only £5m of £18m. check_slide passed it anyway.. “{"id":"J2","ok":true,"msg":"Body supports the claim"}”: The agent rewrote the title to satisfy R12 ('The title has no figure; quantify the so-what') and R1 ('Title runs to 3 lines'). That squeezed 'led by a step-change at' into 'driven by', which is a stronger causal claim. J2 then confirmed the overstated claim, so the agent reported 'All checks pass'. Fix: Make J2 test causal words ('driven by', 'led by') against the data: fail when the named event accounts for less than half of the change the title quantifies. Add to R12's message: 'keep any cause you name proportionate to the data.'
- **n01#1** Auto mark resolved to a line. The line shows only the end value, so the June and July figures the user wants explained never appear on the slide.. “"resolved":{"chart.series[0].mark":"line"}”: The card says 'Values are written on the data', so the agent assumed every month would be labelled. With the line mark only the last point gets a label (£36m), and the agent did not notice that £31m and £30m were missing. Fix: Change the card text to 'Values are written on the data (bars: every value; lines: the last value only — add callouts for any other point the request names)'. Have the write return a warning when the request names categories (June, July) whose values are not labelled.
